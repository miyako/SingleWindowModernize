# 日本語デモ用の架空顧客データ

デモとスクリーンショット用の**固定された架空の顧客200件**を使用します。
以前準備した国税庁の実在法人データは採用せず、そのデータファイルと専用の取得ツールを取り除きました。

データの実体は次のファイルだけです。

[`demo/4D Invoice/Resources/ja.lproj/Clients.txt`](../../demo/4D%20Invoice/Resources/ja.lproj/Clients.txt)

## 内容と形式

- 顧客名は「デモ文具001（架空）」などの連番付きの架空名です。
- 所在地は「架空県」「サンプル市」「見本町」などの架空の所在地です。郵便番号の`0000000`はダミー値です。
- 電話・携帯電話・FAX・メール・担当者は空欄です。実際の連絡先は含みません。
- ヘッダーなし、11列、タブ区切り、UTF-8（BOMなし）、LFです。
- 列順は、会社名、住所、市区町村、都道府県、郵便番号、国、電話、携帯電話、FAX、メール、担当者です。
- **行末の5つのタブは空欄の列を保持するために必要です。削除しないでください。**

`FillData`の既存の`Get localized document path("Clients.txt")`が、日本語ローカライズ時にこのファイルを探します。
英語などの元の顧客ファイルと英語へのフォールバックは変更していません。
一時コピーの空のデータベースで、200件すべての11項目が元ファイルと一致することを確認しています。

顧客ファイルは静的です。起動時に顧客をランダム生成したり、外部サービスから取得したりしません。
一方、既存の`FillData`による商品価格・請求書・日付などのランダム生成は、この変更の対象外です。

## 再現

`tools/demo_customers.py`は、ネットワークも乱数も使用せず、同じ200行を生成します。
4Dの実行時には使用しません。リポジトリルートで確認できます。

```sh
.venv/bin/python tools/demo_customers.py --check
```

初回生成は次のコマンドです。既存ファイルの内容が異なる場合は、編集内容を保護するため上書きせず停止します。

```sh
.venv/bin/python tools/demo_customers.py
```

4Dでの読み込みと日本語表示用データの確認は、`tools/tests/demo_ja.4dm`を使用します。
`tools/tool4d.py`がプロジェクトを一時コピーするため、元のデータファイルは変更しません。
商品コード240件と元の税率も照合します。フォームの見た目は、このヘッドレス実行では確認できません。

```sh
.venv/bin/python tools/tool4d.py "demo/4D Invoice" tools/tests/demo_ja.4dm --new-data
```

テンプレートのデータ保存・更新は、次の独立したテストで確認できます。

```sh
.venv/bin/python tools/tool4d.py "demo/4D Invoice" tools/tests/demo_templates.4dm --new-data
```

日本語のメニュー・ラベルの収まり、請求書エディター、Write Proの表示は、フルGUI版4Dでの確認が必要です。
この環境でのWrite Proを含むヘッドレス試行は異常終了したため、その動作は確認済みとはしていません。

文書のコードと数値、元PDF、英語スクリーンショットは変更していません。
文書中のコード例は原著のままです。日本語デモにはXLIFF参照や表示ラベルの処理を追加しているため、
該当するメソッドは文書のコード例と逐語的には一致しません。
